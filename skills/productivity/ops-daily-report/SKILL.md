# OPS 三段式日报

把用户粘贴的当天工作记录，整理成一份可直接发送的三段式日报。

核心约束：日报正文严格只有三段；不丢信息、不改关键名词、不编造进度；`今日投入` 各项合计必须为 100%。

## 输入

用户直接粘贴当天工作，格式不限：自然语言、`1:`/`1、`/`1.1` 混编、commit、MR、钉钉文档链接、命令、报错都可能出现。

## 工作流程

1. 定日期：用 `date '+%Y-%m-%d %A'` 确认；用户语境里的日期优先于系统日期。
3. 归并：把零散记录聚成 2~5 条主条目（同一项目/同一域的碎片合并成一条，明细下沉到 `1.1`），按当日投入从大到小排。
4. 生成正文：按下方格式写全三段，第二段字段一个不缺。
5. 自检：跑一遍「自检清单」，不通过就改，别交出去。
6. 落地：日报目录存在时写入 `日报-YYYY-MM-DD.md` 并把全文展示给用户确认；目录不存在则只在对话里输出。用户提改动时用精准编辑，不要整篇重写。

## 输出格式

完整骨架见 `assets/template.md`（唯一格式基准）。要点：

- 三个段标题固定为 `一、今日完成:`、`二、当前跟进需求与投入:`、`三、负载说明:`（半角冒号，与历史日报一致）；字段内部用全角冒号 `角色：`。
- 第一段：主条目 `1.` `2.`；明细 `1.1` `1.2`，缩进 2 空格。
- 第二段：`N. 事项 --- 状态`，空一行，再写 7 个字段，每行缩进 2 空格。
- 第三段：固定两行，`三、负载说明:` + `今日投入合计：100%`。
- 一、二两段的条目编号与命名严格一一对应（第 2 条讲的必须是同一件事）。

## 字段规则

第二段每条必须输出全部 7 个字段，顺序不变：

| 字段 | 规则 |
| ---- | ---- |
| 角色 | `ops`（运维/架构/线上处置）、`golang`（写代码为主），默认 `ops` |
| 当前完成度 | 百分比，或状态词（`已完成`/`已修复`/`0%（未开始）`）。用户没给就按事项状态写状态词，不要凭空造百分比 |
| 今天目标 | 通常与完成度同值；有推进时写 `40%（昨日 30%）`；也可写一句目标描述 |
| 预计完成 | 通常与完成度同值；已交付写 `已完成` |
| 今日投入 | 百分比。所有条目相加 = 100%，这是硬约束 |
| 卡点 | 无卡点写 `无`；有则写一句具体卡点（如 `待放行 test-zy NAT 出口 EIP 的 5432 入站`）。绝不填百分比 |
| 风险 | 默认 `无`，确有风险才写具体描述。绝不填百分比 |

投入占比缺失时：按各事项工作量给出估算值凑满 100%，并在日报正文之外用一句话提示用户「投入占比为估算，请确认」。正文里不留 `未填写`。

## 整理规则

- 保真优先：项目名、工具名、集群/namespace、镜像 tag、commit、文件路径、接口名、链接一律原文照抄，不改写、不缩略。
- 兼容无需求号：
  - 有需求号：`【需求号】【类型】事项 --- 状态`（如 `【ZYOP-5】【bug 修复】修复删除用户失败 --- 已修复`）。
  - 无需求号：`【项目/域】事项：一句话结论`（如 `mcp 二期开发部署：已部署到 test 环境`、`工具建设：…`、`线上稳定性：…`）。
- 结果导向：说明句动词开头、给结论（`排查并解决…`、`完成本机搭建并端到端走通…`、`推进…接入`），不写过程流水账。
- 不增戏：可调语序让人读懂，但不补充用户没说的事实，不编造完成度/卡点/风险。
- 状态词收敛：`已完成` / `已修复` / `跟进中` / `持续跟进中` / `未开始`。
- 中文标点；`1、` 或 `1.` 跟随最近一篇日报的写法，全篇统一。

## 自检清单

交付前逐条确认（历史日报真实踩过这些坑）：

- [ ] 只有三段，没多出「总结」「备注」「模板说明」等小节
- [ ] 第二段编号连续且不重复（曾出现 `1. 1. 2.`）
- [ ] 一、二两段条目数量、编号、命名一一对应
- [ ] 7 个字段每条都全，无缺行
- [ ] `卡点` / `风险` 不是百分比（曾出现 `卡点：100%`）
- [ ] `今日投入` 各项相加正好 100%，且与 `今日投入合计` 一致
- [ ] 链接、commit、路径与输入原文一致
