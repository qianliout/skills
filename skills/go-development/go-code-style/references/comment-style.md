# Go 注释硬约束

注释只补充代码、命名和类型无法表达的信息。所有代码注释必须使用中文；标识符除外。注释任务同时必须遵守 `code-style.md` 的命名和层职责约束。

## 必须写注释的情形

- 必须为业务规则、历史兼容、外部协议、特殊单位、性能限制、幂等约束、事务边界、缓存边界、并发边界、危险副作用以及看似可删但实际不可改的逻辑写注释。
- 字段存在额外语义时必须写清楚该语义，例如第三方原始状态与内部状态的优先级、毫秒时间戳以及 `0` 的特殊含义。
- 导出函数、类型或方法承担状态机、生命周期、外部协议、特殊存储映射或不可从名称推导的契约时，必须写明约束、调用条件或后果。

## 禁止写注释的情形

- 禁止为见名知义的字段、函数、类型写注释。
- 禁止写中文翻译、标识符复述或显然控制流描述，例如 `// ID 主键ID`、`// UniqueID 唯一ID`、`// Name 名称`、`// GetUser 获取用户`、`// 返回错误。`。
- Model 的常规字段默认禁止注释：`ID`、`UniqueID`、`Name`、`Status`、`CreatedAt`、`UpdatedAt`、`DeletedAt`。
- 禁止保留容易过期且未提供额外约束的注释。
- 命名、抽取局部变量或拆分函数能够表达时，必须改代码；禁止用注释兜底。

## 质量门禁

- 注释必须简短、中文、可长期维护，并解释原因、约束、边界或历史背景。
- 删除注释后不会误解业务约束时，必须删除该注释。
- 评审时必须逐项确认：注释是否表达代码无法表达的原因、边界或历史背景；是否应以改名、抽变量或拆函数替代；是否只是标识符翻译。
