# Commit Review

显式调用的改动审查执行器。规则来自本仓库既有的规则 Skill，本 Skill 只负责确定范围、装载规则、逐条比对、输出可拍板的问题清单。

## 触发与边界

- 只在用户显式输入 `/commit-review` 时运行；任何情况下不得自动触发，也不得被其他 Skill 当作子流程调用。
- 审查阶段严格只读：禁止修改任何文件，禁止运行 `goimport`、`go test`、`go vet`、lint、构建，禁止任何写操作的 git 命令。
- 与 `code-quality` 的边界：`code-quality` 是模型自动触发的通用质量入口；本 Skill 是用户显式触发的改动审查执行器。两者只共享 P0–P3 严重级定义，本 Skill 不加载 `code-quality` 的 reference。
- 不审查 commit message 规范。

## 参数

| 输入 | 范围 |
|------|------|
| 无参数 | 最近 5 条提交 + 暂存区 + 未暂存工作区改动 + 未跟踪新文件 |
| `<sha>` / `<ref>` | 只审该提交自身的 diff |
| `<sha> <sha> ...` | 逐个审这些提交 |
| `A..B` | 审该区间的每个提交 |
| `--staged` | 只审暂存区 |

解析不出参数时报错并列出上表，禁止猜测范围。

## 强制工作流

1. 确认位于 git 仓库；否则直接说明无法执行，不做降级猜测。
2. 按参数确定范围，用只读命令收集改动：
   - 提交列表：`git log --oneline HEAD~5..HEAD`（提交数不足 5 条时用 `git log --oneline` 全量，并说明实际条数）
   - 合并提交：`git rev-list --min-parents=2 <range>` 识别后跳过
   - 单个提交：`git show --format= <sha>`
   - 暂存区：`git diff --cached`
   - 工作区：`git diff`
   - 未跟踪：`git ls-files --others --exclude-standard`
3. 过滤文件（见下）。
4. 规模保护：改动超过 40 个文件或 2000 行时，先只输出按提交/模块分组的范围清单和问题分布预估，请用户选择子集后再逐条审。
5. 按「规则源路由」装载规则 Skill；只装载实际命中的，禁止全量装载。
6. 逐条比对产出 findings。判断分层和职责时必须读改动文件的就近上下文：接口、构造函数、调用方、测试。
7. 输出报告后停下，等用户回复要修的编号。禁止在报告阶段顺手修改。
8. 用户指定编号后进入修复阶段：按对应规则 Skill 的要求实现，此时才补 `goimport` 和最小范围 `go test`，不能跑时说明原因。

## 规则源路由

| 命中文件 | 装载 |
|----------|------|
| `*.go` | 先装载 `go`（强制总入口），恒定装载 `go-code-style`，其余按 `go/SKILL.md` 的路由表根据实际触及的层装载 |
| 其他文件类型 | 暂无规则包；列入「未覆盖」小节，不臆造规则 |

新增语言只在本表加一行并指向对应规则 Skill，不在本 Skill 内维护规则正文。

## 文件过滤

跳过：合并提交、`vendor/`、`*.pb.go`、`*_gen.go`、`wire_gen.go`、`mock_*.go` 等生成物、纯删除的文件。

审查：`_test.go` 要审（走 `go-test-writer`）；未跟踪的新文件按全文审查；被 `.gitignore` 排除的不看。

所有跳过项必须在报告末尾列出数量和原因，禁止静默丢弃。

## 严重级

- `P0`：安全漏洞、数据损坏、明显正确性错误、阻断发布。
- `P1`：高概率逻辑错误、严重设计缺陷、显著性能或稳定性回归。
- `P2`：可维护性问题、中等风险代码味道、测试缺口、非阻断性行为风险。
- `P3`：风格、命名、轻微结构建议。

工作区和未跟踪文件属于未完成状态，该区默认压制 P3 类挑刺，只保留会延续到提交的问题。

## 输出格式

报告用中文；建议代码中的注释和日志用英文。findings 在前，汇总在后，按来源分三区，编号全局连续且稳定。

```markdown
## 范围
- 已提交：<n> 个提交（<sha> …）｜ 暂存：<n> 文件 ｜ 工作区：<n> 文件 ｜ 未跟踪：<n> 文件
- 装载规则：go、go-code-style、go-service-layer …

## 已提交
### F1 ｜ P1 ｜ `path/file.go:120`
- 出处：go-service-layer / references/service-layer.md
- 现状：…
- 建议：…（代码片段，不落盘）
- 影响行为：是 / 否

## 暂存区
### F2 …

## 工作区
### F3 …

## 其他风险（规则未覆盖）
- …

## 存量问题
- [存量] …（最多 10 条）

## 未覆盖与跳过
- 跳过生成物 <n> 个、合并提交 <n> 个、无规则包文件类型 <n> 个

## 汇总
- P0 <n> ｜ P1 <n> ｜ P2 <n> ｜ P3 <n>
- 回复要修的编号，如 `F1 F3` 或 `全部 P0/P1`
```

没有发现问题时，必须写清已审范围和未覆盖的风险面，禁止只回一句「没问题」。

## 禁止清单

- 禁止在审查阶段修改文件或运行构建、测试、格式化、lint。
- 禁止全量装载规则 Skill，禁止因调用链上存在某层就装载该层。
- 禁止输出没有出处的规则类 finding；规则未覆盖的问题只能放「其他风险」。
- 禁止静默截断 findings 或静默跳过文件。
- 禁止在本 Skill 内维护或粘贴各语言规则正文。

## 交付门禁

- 已列出实际审查范围、装载的规则 Skill、跳过项。
- 每条 finding 有编号、严重级、文件位置、出处、建议。
- 审查阶段没有产生任何文件改动。
- 已提示用户按编号选择修复项。
